From Node.js to FastAPI

I've been working with Node.js for a long time, mostly with Express and TypeScript. So when I recently started working with FastAPI, I expected Python to feel like a completely different backend world.

Surprisingly, it didn't.

The API layer felt very familiar. Routes, async/await, dependency injection, request validation — a lot of the concepts I was already used to were there, just expressed in Python.

What made the transition even smoother was the tooling.

With uv, the Python project workflow felt surprisingly close to what I'm used to in Node.js: pyproject.toml, uv.lock, version management, and project configuration all made the ecosystem feel much less foreign.

Then came SQLAlchemy + Alembic.

Coming from Node.js, I immediately recognized the value of having proper migrations and schema management. And yes, Node.js has similar tools — Prisma, TypeORM, Sequelize, Knex, Drizzle, etc. It's just that in the Python ecosystem, Alembic felt like a very natural companion to SQLAlchemy.

The other thing I keep thinking about is AI.

Python is so deeply embedded in the AI/ML ecosystem that learning more Python feels increasingly useful beyond just backend development. FastAPI seems to sit nicely at that intersection — you can build a backend in Python while staying close to the ecosystem where a lot of AI work happens.

So far, my biggest realization isn't that FastAPI is "better" than Node.js.

It's that the backend engineering concepts I've learned over the years transfer surprisingly well.

The language and tooling changed, but the mental models didn't.

And that made moving from Node.js to FastAPI feel less like starting over and more like adding another tool to my toolbox.
